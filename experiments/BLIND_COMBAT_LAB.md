# 未知抽牌条件下的离线战斗搜索

> 2026-09-20 后续核查：下文旧版三组比较的混合汇总不能继续作为真实游戏机制下的策略证据。原生引擎将 Rage 费用算作 1（实际为 0），影响 f1a67c5c F33；Doubt 的内部费用 -3 未转换为协议的 -2，影响 f1a67c5c F18 的输入一致性。原始结果保留，各目录追加 validity-notice.json。预算与头槌记忆的新对照及费用修正见 [后续实验](SEARCH_MECHANISM_ABLATION.md)。


本实验推进的是“先建立可信比较，再决定是否替换策略”。没有线上策略开关，没有启动游戏，不能把模拟胜率当作整局或心脏击杀率。

## 实现

- `native/blind_combat_lab.cpp` 以 JSONL 提供离线 start/view/search/step。执行世界由进程持有；搜索复制状态后替换全部六条未来 RNG 流，并对按实例 ID 排序后的未知抽牌堆重新采样。规划种子与实际执行种子分开。根节点按世界等权聚合，使用上游完整战斗搜索及根动作选择器。
- `blind_combat_benchmark.py` 在相同初始世界上分别执行当前 `SimpleAgent.get_next_action_in_game` 战斗入口的有序/未知牌序对照和新搜索，按三分支校验初始状态摘要一致（仅归一化声明的牌序可见性差异，原始观察摘要也保留），保留逐决策行动、候选统计和延迟。各分支禁用药水；结束回合、选牌、攻击都必须匹配原生合法动作及观察版本号。
- 支持范围显式限制为这批铁甲牌组、遗物和三个第二幕遭遇。其余角色、遗物和选择界面报错，不能当作输赢。根动作列表保留重复牌的实例，避免把“选择另一张相同牌”误判为非法。
- Java 协议新增已发生的出牌分类计数、能力牌计数、生成球历史、遗物触发状态、卡牌战斗费用及动态字段；日志保留敌人动作编号、历史、球位、相关计数及结算中卡牌。字段缺失保留为缺失，不补零；Runic Dome 不额外暴露隐藏意图。

上游固定为 `Attemory/sts_lightspeed@46e14e4adc23d2c1c738df8902a6f297109fee50`，MIT 许可证保留在独立检出目录。本实验链接其原始实现，没有修改上游。状态字段设计参考了 `AttemorySystem/spire-agent` 的公开状态补丁，并核对本机游戏 JAR 的字段/方法；没有使用其 RNG 导出补丁。

## 比较口径与限制

1. 这是用历史永久牌组、遗物、血量重新生成的遭遇，不是历史战斗回放。入场遗物计数可能已经消耗过，不能据此断言原局本应获胜。
2. 初始状态配对相同；两策略选牌不同后，抽牌、洗牌及随机流的消耗允许自然分岔。不能要求之后每回合手牌仍相同。
3. 新搜索不知道真实未来抽牌顺序和 RNG，但仍复制原生模拟器的怪物内部状态。它尚未从真实协议重建全部状态，不能宣称拥有与真实玩家完全相同的信息。
4. 每个采样世界中的后续规划可见该假设世界的未来，存在对理想续招过度乐观的问题；“找到胜利的采样世界数”不是校准过的获胜概率。
5. 实验暂时忘记 Headbutt 设置的已知牌堆顶；当前策略在该选择界面使用自身的 retrieval scorer，并非完整生产选择界面处理。两者都需要在上线前补齐。
6. 只比较战斗执行；没有测试选牌、路线、商店、药水规划，更没有验证心脏击杀率。终局 HP 是原生战斗 HP，未加战后 Burning Blood 等恢复。
7. 搜索沿用上游默认根动作最少 2048 次访问；在每世界 600 次模拟的预算下，根节点主要均分访问。是否应把探索预算与实际总预算匹配，是下一项受控实验，而不是已经验证的优化。
8. 调用了上游根动作选择器，但尚未填充其全部直接结束回合边界证据。不能宣称上游所有防御支配检查已经完整接入。

## 独立复核与三组对照

原验证任务完成离线代码审查并成功向本任务回传完成通知。审查发现：未知牌堆排序后，当前策略仍把该顺序当作确定未来；此外存在最终预算动作达到终局时误记 cutoff、Defect 字段名不一致、报告来源摘要不全的问题。均已修复并新增回归覆盖。`blind-paired-corrected-20260920` 的 22 对 23 结果因此也作废，不能作为策略比较证据。

新的 `draw_pile_order_known` 贯穿观察、Game、beam 初始状态与精确抽牌入口。显式未知时，Offering/抽牌药水等不再宣称确定的续招；旧协议默认保留现有行为。新的实验包含：当前策略保留真实协议牌序、当前策略明确不知道牌序、新搜索独立采样未来。不能通过削弱当前策略的输入而宣称实际收益。

生产敌人实例绑定仍未被离线 token 接口验证，作为明确的上线阻断项保留。审查中关于 Gremlin Horn 缺少 counter 的疑虑，经同初始状态、同动作、有/无遗物的两个原生进程对照，确认击杀触发的能量和抽牌在观察中正确体现；其没有待导出的持续计数，当前预测器较弱属于策略能力差异，不能据此认定观察接口缺字段。

独立验证任务的增量复核已确认上述牌序、统计和字段名问题闭合，并撤回 Gremlin Horn 观察缺字段的判断。两次复核均成功通知本任务；完整意见保存在 `results/blind-review-20260920.md`。真实状态重建与生产绑定仍然是上线阻断项。

## 最终三组对照结果

有效结果位于 `results/blind-three-arm-20260920/report.json`。每场景取执行世界 0–7；新搜索每次决策取 4 个独立规划世界、每世界最多 600 次模拟（允许确定性提前收敛），每场最多 250 次决策。32 组三分支初始状态全部匹配，各分支均完成 32 场，没有错误、超时或截断。

| 原对局 / 楼层 / 遭遇 | 当前保留牌序：胜利 / 平均 HP | 当前未知牌序：胜利 / 平均 HP | 新搜索：胜利 / 平均 HP |
|---|---:|---:|---:|
| afcd85ad / 18 / 球形守护者 | 8/8 · 61.625 | 8/8 · 61.625 | 8/8 · 43.625 |
| afcd85ad / 33 / 铜制机械人 | 6/8 · 18.250 | 6/8 · 18.250 | 7/8 · 27.750 |
| f1a67c5c / 18 / 球形守护者 | 8/8 · 54.500 | 8/8 · 54.500 | 8/8 · 58.250 |
| f1a67c5c / 33 / 冠军 | 0/8 · 0 | 0/8 · 0 | 0/8 · 0 |
| 合计 | 22/32 · 33.594 | 22/32 · 33.594 | 23/32 · 32.406 |

HP 均值包括死亡样本（记零），尚未加战后遗物治疗。按决策次数加权的平均每次决策耗时分别为 32.8ms、32.6ms、209.8ms，同机非隔离计时仅供成本参考。结果绑定原始报告的源码摘要及 `source-snapshot.zip`；同样的牌组与原始种子重复模拟，不能视为 32 个独立整局。这里未发现两个当前策略分支的结果差异，不等于未知牌序契约没有必要。

**当前不切换线上策略，也不冻结新搜索跑六局。** 铜制机械人的改善是正向信号，但 afcd85ad 的球形守护者八组全部更亏血，冠军仍八组皆败，整体平均终局血量也略低。没有足够证据说明它会提高整局或心脏击杀率。

具体反例：`afcd85ad-f18.input-w0-*.json` 中第二回合、decision 2 开始分岔。两个当前策略分支均使用 Pommel Strike，后续防御并在第 5 回合以 66 HP 获胜；新搜索先两张 Defend，再 Inflame，第 6 回合以 57 HP 获胜。新搜索每个根动作累计约 264–268 次访问（四世界合计），按假设世界中找到的最佳续招比较动作。决策与结果差异由日志直接证明；有限预算、理想续招的乐观偏差、Headbutt 已知牌堆顶丢失各贡献多少，尚不能分解。

下一轮优先做受控的根动作预算实验、保留已知牌堆顶，以及用真实协议核对一步转移；再看能否在固定样本上改善死亡率和剩余血量。无需增加一批怪物专属评分规则。

## 检查结果

- Java 模块离线编译通过；未部署 JAR、未重启游戏。
- 全量 Python 单测 2,914 项通过；另有 14 项实验检查通过，覆盖隐藏未来不变性、搜索不消耗执行 RNG、重复牌实例绑定/过期动作拒绝、明确拒绝范围外状态。
- 历史 DecisionCase 6,968 例检查为 clear：2,324 例直接审计、2,091 例明确不适用、2,553 例已有解决证据；issue、eligible unknown、unresolved 均为零。它们不是 6,968 次新搜索对局验证。
- 新增 4 项未知牌序/抽牌池边界测试，以及 3 项日志边界测试包含在全量单测中，检查缺失与零值、动态牌及敌人历史、隐藏意图不会凭空出现。

## 其他无效实验的处理

`blind-smoke-01`、`blind-smoke-02`、`blind-paired-20260920` 的报告均标记 `valid_comparison: false`。原因是最初输出了原生引擎从零开始的回合号，而 CommunicationMod 从一开始；上游 `BattleConverter.cpp` 的反向导入也明确执行 `combatTurn - 1`。已改为输出 `bc.turn + 1` 并增加边界检查，原结果保留供调试，不并入正式统计。

## 复现

先按 `LIGHTSPEED_PILOT.md` 准备固定版本源码和本地构建工具，然后运行：

```powershell
./experiments/build_blind_combat_lab.ps1
python -m unittest experiments.test_blind_combat_lab test_combat_snapshot_history -v
python experiments/blind_combat_benchmark.py --inputs experiments/results/lightspeed-20260920-v3 --output experiments/results/your-new-output --execution-worlds 8 --search-worlds 4 --simulations 600 --max-decisions 250
```

输出目录必须新建，避免覆盖证据。报告及源码归档保存二进制、源码及基线策略源码 SHA256、固定上游版本、配置、原始输入和每组结果。超时、适配错误与截断单独统计，批次存在此类问题时命令返回非零。

上线前仍必须完成真实协议状态重建、关键一步转移对照、已知牌堆顶记忆、药水与选择界面处理、原生动作到生产实例绑定、完整回放及冻结检查。只有通过这些检查且对照结果足够支持，才由原验证任务执行六局实战并回传完成通知。
